6.1  The pipeline architecture as it exists in the code
     POST /ai/analyze-clothing (server.js:600)
       -> decode once: imageBase64 raw, data URL, or /storage/ reference
       -> sniffImageMime + readStoredImage (magic bytes, path guard)
       -> ai.analyzeClothing (ai-engine.js:636) async
          -> imageBytesFor/imageBytesOf (ai-engine.js:670+)
          -> analyzeClothingImage(bytes, overrides) (clothing-vision/index.js:58)
             -> encoder.js: lazy CLIP towers from backend/.model-cache, one
                prompt bank built once and reused
             -> classify.js: clothing vs non-clothing gate (margin, clothingMass)
             -> color.js: segmentation + CIELAB LCh measurement
             -> index.js: formalityFor(), applyOverrides(); a rejection is
                returned untouched
       -> on rejection: HTTP 422 { analysis, source:'clothing-vision',
          rejected:true } and NO remote refinement (server.js:635-638)
       -> otherwise optional Gemini/Groq refinement that may fill uncertain
          attributes but cannot overwrite a decided category or measured colour
          (server.js:647-667)
     Wardrobe save (server.js:461-552) re-analyses the bytes itself so a row
     always carries provenance, and DELETE is a soft delete (archived=true,
     server.js:568-574) so outfit history survives.

Priority order. Items 1-3 are the ones that break the product for a real user.

1. CRITICAL - The 8 s client timeout cannot survive the server's cold start, and
   it has now failed in production.
   Evidence: api_config.dart:26 `timeout = Duration(seconds: 8)`;
   aiUsage 10-05 17:05:00 = 28,909 ms accepted; the two e2e suites measured
   37,498 ms and 37,173 ms for the first analyze after a server start; the

   or persist the bank; or raise the timeout on this route only.
